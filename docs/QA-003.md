# QA-003 — diagnóstico previo a cambios

La inspección se realizó únicamente sobre código; no se consultaron ni modificaron credenciales existentes.

## Causa raíz comprobable

`resources/views/credentials/index.blade.php` presenta en `.secret` la concatenación de `username + ' / ' + password`, no el valor exacto de la contraseña. Esto altera el texto presentado cuando existe usuario. No hay evidencia de corrupción criptográfica ni de sustitución automática por el generador: este solo se invoca mediante su botón explícito. No se puede atribuir una discrepancia histórica adicional sin reproducirla; no se han leído secretos reales.

Además, `CredentialController::update` usa `empty(password)`, que trata la cadena `0` como vacía y conserva el secreto anterior. Actualiza también la fecha de cambio aunque no cambie la contraseña. No existe botón Copiar en la vista actual.

## Recorrido auditado

El formulario envía `password` directamente. Laravel excluye `password` del recorte de espacios. El controlador cifra ese valor con la DEK de sesión mediante `VaultCrypto::encrypt`. Se guarda únicamente `password_enc` en una columna longText. El formato es base64(nonce + secretbox); `decrypt` separa el mismo nonce y autentica/descifra con Sodium. El endpoint de revelado devuelve el resultado descifrado, no base64. Bloquear invalida la sesión; desbloquear deriva la KEK con Argon2id y recupera la misma DEK envuelta. Editar deja la contraseña vacía para conservarla o cifra el reemplazo con un nonce nuevo. Los eventos de auditoría no reciben el secreto. VaultCrypto no requiere cambios.

## Corrección prevista

Mostrar exclusivamente la contraseña mediante textContent. Copiar mediante el mismo endpoint de descifrado autorizado, sin obtener el texto compuesto de la fila. Conservar el ocultamiento temporal y permitir ocultar inmediatamente. Corregir la condición de reemplazo y la fecha. Validar que las contraseñas sean cadenas. Añadir pruebas PHP con SQLite en memoria y pruebas JavaScript con secretos sintéticos, comparaciones booleanas y mensajes sin valores secretos.

## Resultado y archivos

- `app/Http/Controllers/CredentialController.php`: condición explícita de reemplazo, validación string, fecha solo al cambiar contraseña y respuesta no-store.
- `resources/views/credentials/index.blade.php`: integra Copiar y el script compartido.
- `public/credential-secrets.js`: revela únicamente password, copia el valor descifrado, oculta manualmente o a los 15 segundos y maneja errores sin registrar secretos.
- `tests/Feature/CredentialSecretTest.php`: creación, almacenamiento cifrado, revelado, bloqueo/desbloqueo, edición vacía, reemplazo y nuevo desbloqueo; símbolos, espacios, Unicode, 8192 caracteres y cero. Antes del cambio reprodujo el fallo de edición con una aserción sin datos sensibles.
- `tests/Unit/VaultCryptoTest.php`: autenticación, rechazo de alteraciones y clave incorrecta, nonce nuevo.
- `tests/js/credential-secrets.test.mjs`: revelado exacto con usuario presente, portapapeles, ocultamiento, fallos y generador solo por invocación explícita.
- `package.json`: comando npm test; este documento registra el diagnóstico antes de la modificación.

Verificación: `php vendor/phpunit/phpunit/phpunit --no-progress` y `npm test`. Las pruebas PHP usan exclusivamente SQLite en memoria; JavaScript usa DOM y portapapeles simulados, no un navegador real ni el portapapeles del usuario. No había pruebas previas en tests. No se cambió VaultCrypto, no se ejecutaron migraciones contra la base real ni se inspeccionaron credenciales existentes. No hay reparación automática de datos históricos.

Resultado final: PHP, 2 pruebas y 157 aserciones aprobadas; JavaScript, 2 pruebas aprobadas. En PowerShell se ejecutó `npm.cmd test` porque la política local impide cargar npm.ps1. La comprobación de sintaxis PHP del controlador también pasó.
